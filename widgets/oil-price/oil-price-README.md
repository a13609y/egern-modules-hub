# 全国实时油价 · Egern 小组件模块

92 / 95 / 98 号汽油与 0 号柴油实时油价 + **真实官方调价历史走势**，三套尺寸布局，深浅色自适应。

- 现价源：<http://m.qiyoujiage.com>（省份/城市页面解析；站点改版可能失效，失败回退上次缓存）
- 历史源：**BesFuel** 已逐期核实的发改委调价历史（元/升真实节点，见下文「历史从哪来」）
- 支持尺寸：小号 `systemSmall`、中号 `systemMedium`、大号 `systemLarge`（锁屏 accessory 尺寸只显示单价）
- 组件名：**实时油价**

## 安装

1. Egern → 工具 → 模块 → `+` → 粘贴模块地址：

```
https://raw.githubusercontent.com/a13609y/egern-modules-hub/main/widgets/oil-price/oil-price.yaml
```

2. 保存后点开该模块，在「参数」里填地区（默认 `hainan/haikou`）。
3. 回主屏幕长按 → `+` → Egern → 选尺寸 → 长按组件 → 编辑小组件 → 选择「实时油价」。

### 图表怎么画（v4.4.0）

- **最多最近 10 轮**：只渲染序列最后 10 个**真实历史节点**（`slice(-10)`），节点日期/价格原样取自 BesFuel，不补点、不插值、不伪造「第 N 轮」。
- **普通直线连接**：相邻真实节点之间是直线段；直线只表示两次真实调价之间的价差趋势，**不是逐日价格**，也不代表任何中间值。
- **浅橙渐变面积**：折线到基线之间用 `linearGradient` 橙色 0.34→0.02 的半透明面积做视觉强调。
- **节点与末点**：普通调价为橙色实心圆点，官方「不作调整」为空心圆点；最新一个节点用**绿色大圆**强调，**不写末点价格标签**（参考图无价签，也避免遮挡折线与坐标文字）。
- **缺口不连**：`historyGaps` 命中的位置把折线与面积都断开成多段，不跨缺口连线。
- **坐标轴**：X 轴首/中/尾三个**真实日期**（`M/D`，节点>3 时才画中间标签，先量宽再决定，不切边不重叠）；Y 轴三条刻度取**真实最大/中值/最小价格**，不虚构数值。
- **1 点 / 空态**：只有 1 个官方节点时画单点图（真实日期 + 真实价格刻度，图注写「仅 1 轮」）；无序列时才显示「未收录 / 暂不可用」占位块。

## 历史从哪来（BesFuel 研究结论）

`m.qiyoujiage.com` 本身**只有当前价和最近一次调价文案**（`tishi`），`/tz/YYYY.shtml` 只有调价日期表，`/fujian/lishi.shtml` 等历史地址均 404（`curl` 实测）。所以原来「装着等两轮」的走势对新用户一直是空白。

用户指定的 <https://github.com/BensonLaur/BesFuel> 正好解决了这个问题：

- 仓库 `lib/history.js` 从 `data/prices.json` 的 `regions[].grades[].history` 生成阶梯图，节点是**各地发改委公告里逐期核对的「价格执行日期 + 元/升」**，`historyGaps` 记录缺表日期并断线，`latestNotice.kind === "unchanged"` 生成空心的「不作调整」观察节点；`checkedAt` 是核对日期。
- `data/prices.json` 由 GitHub Actions 每天北京时间 10:00 / 20:00 抓取广东等 45 个价区更新（<https://raw.githubusercontent.com/BensonLaur/BesFuel/main/data/prices.json>，实测 HTTP 200、约 415 KB；jsDelivr 与 GitHub Pages 副本同样 200）。**只读公开数据文件，不需要账号、API key、签名或 Cookie**。
- 该文件也给 `nationalAdjustment.nextAdjustment.date`（按 10 个工作日 + 放假安排推算的下轮窗口，官方规则），本组件优先采用它，取不到才退回本地按 10 个工作日推算。

许可与再利用边界（已核对仓库 `LICENSE`、`docs/RIGHTS.md`）：

- BesFuel 自写代码与文档是 **MIT License（Copyright (c) 2026 BensonLaur）**，本组件只借鉴其**图表语义**（阶梯线 / 节点 / 不调整空心点 / 缺口断线）并注明来源，没有复制其代码。
- `data/prices.json` 里的价格、执行日期属于**政府公告事实**，`docs/RIGHTS.md` 明确说明这些第三方数据**不随 MIT 许可转移**。因此本组件只展示事实字段（日期、元/升、价区名、核对日期）并标注来源，不复制公告正文/图片，也不把快照称为官方实时服务。若要再发布该数据，应另行核对原公告站点条件。

## 涨跌预测从哪来（接口合约 · 配额 · 缓存）

预测与「下轮预计调价时间」来自**极数本源 全国油价 API**，合约以官方接入文档为准（<https://apizero.cn/aidocs/oil-price>）。v4.6.1 按用户授权**实测 1 次**（2026-11-18，匿名、`province=海南`、curl 不跟随重定向不重试，失败即止，**全程只调用 1 次**），实测字段与单位见下文「实测记录」。本节把「文档写了什么」「实测看到了什么」「本脚本额外做了什么」分开写。

| 项目 | 文档内容（`[DOC]`） | 本脚本实现 |
| --- | --- | --- |
| 端点 | `POST https://v1.apizero.cn/api/oil-price`，`application/json`，请求体 `{"province":"广东"}`（必填，支持简称/全称、常见城市名自动归属） | 同左；`province` 取模块 `region` 已解析出的中文省级名（如 `福建`） |
| 回包 | `{code, msg, data, tips, request_id}`，**先看业务 `code === 0`**，不能只看 HTTP 200 | 同左；`code !== 0` 一律算失败 |
| 字段 | `data.update_date`（YYYY-MM-DD）、`data.prices[]`（`name/type/price/unit`，`gasoline_92|95|98`、`diesel_0`）、`data.next_adjustment`（如「下次油价7月3日24时调整」）、`data.forecast`（如「预计下调630元/吨(0.48元/升-0.57元/升)」） | 只取 `forecast`（解析方向 + 幅度）与 `next_adjustment`（解析月/日）；现价仍用汽油价格网，不混用两套价 |

### 请求预算怎么保证（如实说明边界）

- **每天最多 1 次请求**，按**北京时间**（UTC+8）日界切分，键 `oilprice_fc_budget_v1`；请求前**先写预算**（`reserved`），再发 HTTP → 中途失败/超时也算今天已用，**不即时重试**。
- **三尺寸共享**：缓存键 `oilprice_fc_v1_<省>` 与预算键都不带尺寸前缀，小/中/大三套 layout 只读同一份数据；同一天里先渲染的那个尺寸发请求，另外两个直接读缓存（测试断言「三尺寸同安装只发 1 次 POST」）。
- **429 / 4029 / 4030**：`state=quota` 当天封停，遵从服务要求不再请求；跨到新的北京日才清空重试。
- **故障关闭**：`ctx.storage` 读不出预算（异常）时**不发请求**，只用已有缓存 → 宁可没有预测，也不盲发。
- **无法硬保证的部分（如实写清）**：Egern `ctx.storage` 是持久化 KV，**没有原子 CAS / 跨进程锁**。同一安装内多尺寸并发渲染理论上存在极小竞态窗口（都读到「今日未用」再各自写入），本脚本用「先写预算再发请求」把这个窗口压到一次 `setJSON` 之内；**跨设备、跨 App 重装/清缓存无法共享预算**（每台设备各自 1 次/天，仍在文档「匿名 5 次/天」限额内）。WidgetKit 的刷新时机由系统调度，本模块不保证每天都能拿到新预测。
- 因为存在上述竞态，本模块**没有**从每个 widget 渲染无条件发请求：请求统一走这一个「预算闸门」，也没有另加定时任务或多设备互斥服务（任务要求不部署额外服务）。

### 实测记录（2026-11-18 · 仅 1 次调用）

授权范围内只发了一次请求，任何失败都不做第二次；命令（不跟随重定向、不重试）：

```sh
curl -sS --retry 0 --max-time 25 -X POST 'https://v1.apizero.cn/api/oil-price' \
  -H 'content-type: application/json' -H 'accept: application/json' \
  --data '{"province":"海南"}'      # → HTTP/2 200, redirects=0, 1228 B, 匿名无 Key
```

实测字段与单位（脱敏样本存 `apizero-real-sample.json`，已删 `request_id`，无任何 Key）：

| 字段 | 实测值 | 单位 / 说明 |
| --- | --- | --- |
| `code` / `msg` | `0` / `cached` | 业务码 0 才算成功；HTTP 200 不代表成功 |
| `data.province` | `海南` | 原样回显 |
| `data.update_date` | `null` | **可能为空**，不能当日期依据 |
| `data.prices[]` | 92号 9.48 / 95号 10.08 / 98号 11.08 / 0号柴油 8.14 | **`unit: "元/升"`，价格已是元/升**（不是吨价） |
| `data.next_adjustment` | `下次油价11月26日24时调整` | 自然语言，脚本只取「月日」 |
| `data.forecast` | `变化率-6.24%，预计下调油价390元/吨` | **本次只有元/吨，没有元/升区间**（与文档示例不同） |
| `data.change_rate` / `change_rate_as_of` | `-6.24` / `2026-11-18` | 原油变化率（非零售幅度），界面不显示 |
| `data.working_day` / `crude_avg_usd` | `4` / `90.78` | 本计价周期第 4 个工作日 / 原油均价，界面不显示 |
| `data.estimated_change_per_ton` | `-390` | 与 forecast 同口径的吨价 |

### 吨价 → 元/升 换算口径（只用于估算，界面标「约」）

实测 forecast 只给 **390 元/吨**，零售价是元/升，所以必须换算；换算依据写死为常量，README 与代码同源：

- **汽油密度 0.725 kg/L**（GB 17930 车用汽油 20 ℃ 密度 0.720–0.775 的常用折算值）
- **1 吨 = 1000 / 0.725 ≈ 1379.31 升** → **元/升 = 元/吨 ÷ 1379.31**
- 实测 `390 ÷ 1379.31 = 0.2827` → 显示 **`↓约0.28 元/升`**（保留 2 位，与最近调价区间同精度；`约`＝估算标记）
- 柴油备用口径 0.835 kg/L（1 吨 ≈ 1197.6 升）已在代码中定义，但当前 forecast 是汽油口径，不启用
- 换算结果 **< 0.005 元/升**（2 位显示成 0.00）或文本里没有方向/幅度 → 一律「暂无预测」，**不把吨价当升价显示**
- 文档示例 `630元/吨 ↔ 0.48-0.57元/升` 隐含 1105~1312 升/吨，与汽油密度口径不一致；本模块**不采用**该隐含系数（无法给出物理依据），只用可公开核对的密度口径，并在界面标「约」以示估算

旧缓存兼容：v4.6.0 可能已把吨价原样写进缓存（`fc.unit = 元/吨`）。v4.6.1 读到旧缓存会就地归一成元/升（`fcv=3`），**只重写 `oilprice_fc_v1_<省>`，不动 `oilprice_fc_budget_v1`** —— 同日预算原样保留，不会因为归一而多发一次请求（回归断言覆盖）。

### 预测的显示规则（绝不把历史/过期/推算说成预测）

预测位只有在**三条同时成立**时才显示幅度：

1. 缓存里有**文档 `forecast` 解析出的方向 + 幅度**（不是历史调价，也不是本地推算）；
2. `next_adjustment` 解析出的**预测窗口在未来**（窗口已过即视为过期，不进预测位）；
3. 缓存 `fetchedAt` 距现在 **≤ 15 天**。

任一不满足 → 统一显示「**暂无预测**」，颜色回落为次要色。最近调价、走势图、现价完全不受预测失败影响（预测源失败时它们照常显示）。「下轮预计调价时间」优先用文档 `next_adjustment` 的月/日（副行标「服务提示」），拿不到时才回退 BesFuel 窗口或本地 10 个工作日推算（标「预计」）——**时间是允许推算的，幅度不允许**。

### 地区 / 油品对应

`region` 先按原有规则解析成省份或省份/城市，再映射到 BesFuel 价区：广东→`guangdong`、福建→`fujian`、海南→`hainan`、北京→`beijing`、陕西/西安→`shaanxi-xian`、云南/昆明→`yunnan-kunming`、西藏/拉萨→`xizang-lhasa`、新疆/克拉玛依→`xinjiang-karamay-main`、内蒙古/呼和浩特→`inner-mongolia-west` 等；省份下有多个价区时取该省主价区并在图注写明完整价区名。`FUEL` 的 92/95/98/柴油分别对应 BesFuel 的 `92/95/98/diesel`。

## 常见问题

**显示「获取失败」**：现价源网络问题或站点不可用；脚本保留上次成功数据（大号底部标「缓存数据」）。历史源独立请求，现价失败时历史仍可能正常。

**显示「BesFuel 未收录该地区」**：该价区还没被 BesFuel 逐期核价（如湖北、甘肃、辽宁目前未导入），或该省只核了部分价区。组件不借用邻近地区数据。

**显示「官方核价历史暂不可用」**：三个历史镜像都失败且本机没有缓存。现价照常显示，下次刷新自动重试。

**历史和加油站价格对不上**：历史是各地**最高零售价**公告值，现价卡是汽油价格网的参考价，二者都可能与某座加油站的挂牌价不同。

**图表不更新**：数据每天 10:00 / 20:00 更新，缓存 6 小时；`refreshAfter` 只是给系统的建议，WidgetKit 实际调度由 iOS 决定。

**图上只有 10 个点**：历史有 20+ 轮，但按参考图只画最近 10 轮真实节点（`slice(-10)`），坐标轴日期/价格都取自真实数据；缺口处会断线，所以段数可能少于 10。
